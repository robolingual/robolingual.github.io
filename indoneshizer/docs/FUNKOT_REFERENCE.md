# ファンコット調査メモ

制作を進める上で確認した事実と、その出典。推測と事実を混ぜないため、
「確認済み」「未確認/仮説」を分けて書く。

## 確認済み

### テンポ
- BPM 180〜200。主流は180。ジャンル全体では160〜220の幅がある。
- 参照音源(制作解説動画)のFL Studio表示は190で、こちらの自動テンポ推定も191だった。

### リズム
- 「ドッタドッドタ」と表現されるドラムパターンが核。英語圏では
  "dot-ta-dot-ta" と表記され、これを Funky Beat と呼ぶ。
- カウベル、ウッドブロックなどのパーカッションが常時絡む。
- 参照音源から実測したキックは16stepの 1, 7, 11 が強く、5, 13 が弱い
  (弱い方はスネアと重なって埋もれていた)。3拍目(step 9)は空く。

### 音色・編成
- 太いベースライン。エレキベースのような音色。
- サンプリングボイスを大胆に多用する("ay!", "are you ready?",
  "one two three four" など)。
- アーメンブレイクの使用が多い。
- 高音域のシンセ。

### 構成
- 曲中でBPMが変わる「DOWN BEAT」展開を持つものが多い。
- ダンドゥット(インドネシアの歌謡曲)のハウス・リミックスが起源。
  歌のフックを残したまま、リズム隊を差し替えるのが基本の作り。

## 未確認 / 今後追うもの

- **三連キック**: 英語圏の記述に "triplet bass kick pattern" とある。
  現在の実装に三連の要素は入っていない。実音源で確認したい。
- **参照音源の数が足りない**: パターンの根拠が、制作解説動画から取れた
  2小節分しかない。複数の実曲で裏を取るべき。

## 作業で踏んだ失敗と、その原因

同じ失敗を繰り返さないために残す。いずれも知識不足ではなく、
**手元の情報を照合しなかった**ことが原因だった。

| 失敗 | 原因 | 防ぎ方 |
|---|---|---|
| ハットを16分裏(偶数step)に置き、表とも裏とも判別できない鳴りになった | 「8分裏」を独自に読み替えた。仕様書8章の譜例 `. . X .` に答えが書いてあった | 仕様書の譜例をそのまま読む。用語は README の定義に従う |
| ハットの実質長が2.24msになり、ハイハットでなくクリック音になった | 「サスティン短め」を極端に適用し、結果を測らなかった | `verify.py` の長さチェックを通す |
| カウベルが22.8msでクリック化していた | 同上。指摘される前に気づけていなかった | 同上 |
| キックの打点を 1, 7, 11 と判定し、5, 13 を取りこぼした | 弱い検出をスネアの漏れと決めつけた | 弱い検出を捨てる前に、他の解釈が成り立たないか確かめる |

## 検証の手順

音を書き出す前に必ず通す。

```bash
cd indoneshizer/backend
python verify.py          # 音色の長さ、打点の位置、実測との一致
python analyze_reference.py   # 参照音源から打点を再解析する
```
